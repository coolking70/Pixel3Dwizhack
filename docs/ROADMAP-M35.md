## 全画面覆盖式 HUD、低误触输入与内容 Beta 2

> **状态：待实施的开发规格，不是已完成结果**  
> 编写日期：2026-10-13  
> 代码基线：`fallen-star-0.31.0-beta.1-source.zip`（M31 / `alpha5-1`）  
> 试玩证据：`fallen-star-alpha5-24681-152.json`；本版继承此前 M31 审查与 M32–M35 v2 规划的已核查结论。

## 0. 核心设计决议（先冻结）

这次更正的重点，不是把 HUD 换到左右两侧，而是**让游戏世界画面继续完整铺满可视区域，HUD 只在世界画面上方的左上角和右上角以轻量组件叠加**。原作 WazHack 的参考价值在于上沿天花板、上层结构等通常较少承担当前层的直接操作；**不应理解成 UI 拥有专用侧栏、画面需要为 UI 缩小或左右留边**。

正式验收原则：

1. **全画幅世界、局部叠加**：Three.js/WebGL 游戏画面在 HUD 下方完整连续渲染；禁止为 HUD 专门裁切世界视口、额外占用左右两栏、添加常驻全宽顶栏或底部操作按钮带。
2. **左上状态，下接短日志**：生命、法力、饱食、异常状态与楼层/区域等必要信息紧凑显示在左上角；其正下方常驻最近 2–3 条日志。点击日志自身展开既有完整日志。
3. **右上最多两个默认一级入口**：建议 `背包/角色` 合一图标、`更多/菜单` 图标。地图、图鉴、日志、设置、帮助、存档/回放、语言等归入二级菜单；已经能从短日志打开全日志，不再常驻一枚日志图标。二级菜单只显示项目当前实际拥有的功能，不创造空页面。
4. **图标是入口，不是操作按钮**：主场景不常驻攻击、开门、拾取、跳跃、拉杆、烹饪、施法、投掷按钮。玩家直接点击场景或在背包详情内选择操作；右上图标只负责进入界面。
5. **事件反馈回世界**：物品/装备/世界设施的正式操作成功提交后，返回主场景；玩家马上能看到世界动画、状态改变及左上日志。失败留当前操作上下文并说明原因；取消只退一层；仅预览、选目标和确认前置环节不算正式操作完成。
6. **HUD 必须让出有效世界操作区**：可交互热区只覆盖实际可见的图标、短日志文字/背景及打开的菜单面板；大片透明填充区域不得吞掉点击。若当前画面上方确有可点击上层梯段、怪物、机关或瞄准目标，必须提供可见提示与动态避让/折叠策略，不能假设“天花板永远不可交互”。
7. **不改变行动驱动时间**：菜单开合、日志阅读、HUD 动画、鼠标悬停、触控长按、摇杆聚焦不增加游戏 tick/revision。只有正式通过核心规则的动作消耗相应时间。
8. **原有确定性逻辑优先**：HUD 和点击意图只能使用公开投影与合法动作查询；未知物品的真实身份、隐藏陷阱、怪物隐性状态不得被 UI 预测/泄露。

### v2 → v3 变更对照

| v2 容易引起歧义的描述 | v3 明确要求 |
|---|---|
| “左侧状态、右侧菜单”容易理解成分屏侧栏 | 左上/右上**叠在全尺寸世界画面之上**，不占世界布局空间 |
| 右上“背包、地图、图鉴、主菜单”等多个快捷入口 | 默认仅 2 枚：**物品/角色**、**更多**；其他功能二级展开 |
| 固定全宽顶栏与底部宽按钮可继续存在 | 正式 direct UI 禁止；保留旧 `?ui=buttons` 作为兼容/开发模式即可 |
| 一次道具使用后是否保留详情存在旧方案分歧 | **被正式接受并完成后回世界**；失败留上下文，取消退一级 |
| 把上方视为永远无操作内容 | 上方空间仅为**优先叠加区域**；实际遮挡必须通过动态安全区和命中检查处理 |

## 1. 界面空间布局规范（不是独立侧栏）

### 1.1 默认横屏示意

下面框内每一个位置都仍属于**同一完整游戏画面**。状态/日志/入口都浮在场景内容之上，而非占有额外的排版列。

```text
┌──────────────────────────────────────────────────────────────────┐
│ [♥ 46/80  ◆MP 15  饥饿121]                     [🎒] [☰]        │
│ [第6层 · 断层工坊 / 状态异常]                                    │
│ 「拾取：线圈钥匙」                      ← 上层石墙、天花板等 →   │
│ 「打开了隔离继电器」                                             │
│     ← 此处仍绘制完整的上层地牢/背景/梯子结构 →                   │
│                                                                  │
│              [玩家]        关卡主体、怪物、地面物品               │
│════════════════════════ 当前游戏地面 ══════════════════════════│
│                                                                  │
│       所有移动、战斗、跳跃和设施互动直接通过场景完成             │
└──────────────────────────────────────────────────────────────────┘
```

图内文字只是说明锚点，不代表必须渲染方框。实际状态区域尽量无框或仅使用**随文字宽度自适应的低不透明度局部衬底**；禁止绘制高度 64/82 像素的整屏横向暗条。

### 1.2 几何与样式建议

- **左上**：离画布安全边界约 10–18 CSS px；状态组件总宽度按内容自适应，尽量不超过可视宽度 30%（移动端适度调整）；优先两行内完成主要状态，生命值更醒目，次要信息较轻。
- **日志**：状态组件下接 2–3 行，常驻刷新；默认不强制持续消失。最近一条事件可用几秒的轻强调效果，但超时消失的只能是强调，**不能自动隐藏全部可见日志**。过长文本单行省略，点击进入完整日志。
- **右上**：仅两个带清晰命中边界的游戏内图标。桌面可小而清晰；触屏有效点击区建议约 40–48 CSS px，仍必须只属于可见按钮附近，而不是透明占据大面积。悬停/长按显示“物品与角色”“更多”等功能名。
- **画面主体**：地面、怪物、物品、跳跃轨迹、攻击预警仍具有最高的视觉注意力。HUD 深色局部衬底的透明度按亮背景保证对比度，避免大面积玻璃卡片或边框。
- **状态来源**：仅用 `PublicView` 公开生命/法力/食物/楼层/异常及可见事件；UI 不存另一份会偏离核心的数值。
- **不应放入 HUD**：自动测试 seed/digest、完整坐标、全部装备数值、所有选项切换、全部临近设施的动作列表等开发调试信息。需要时放二级菜单或 `?ui=buttons` 调试模式。

### 1.3 窄屏与不同视口

- 横屏为主目标，竖屏仍须可用：左上优先保留 **HP + 关键异常 + 1–2 条日志**，次要数值使用展开状态详情查看。
- 两枚右上图标不得覆盖左侧日志；布局用**画布实际可用宽度、安全区域、DPR 与 UI 缩放**计算，而不是写死桌面屏幕像素。
- 过窄时左侧第二行/日志应主动换行或省略，不能把图标挤出屏幕；可让短日志只显示最近一条，但点击依然能打开完整日志。
- 必须考虑屏幕旋转、浏览器缩放 100%/150%、窗口 resize、移动端系统安全边缘以及画布本身缩放后的输入坐标变换。
- 绝不因为画面变窄而回退到旧“底部一排按钮”的正式玩法布局。

### 1.4 遮挡与场景对象

用户提出的上沿天花板、上层梯子及石墙通常是低关注区域，这是一种**布局优先级**，不是保证。设计应：

1. 渲染前可通过公开的 `RoomRenderer` 投影接口获取当前可交互世界对象的屏幕包围盒；如果它与 HUD 的可见交互框重叠，优先把相应 HUD 子块**在顶部有限范围内错位或收紧**，必要时收起非关键文本。
2. 若不可避免的少量遮挡发生在 HUD 后方，交互意图与实际命中规则必须可预测：实际图标/日志区域优先给 UI；在 HUD **外**的邻近投影必须仍可点击梯段/地面。
3. 不要通过让整片顶部区域穿透点击来解决遮挡——那会导致误触菜单后方的世界；也不要通过整条透明顶栏阻挡世界。
4. 打开世界瞄准、确认、重要攻击预警时，暂时缩小日志显示或淡化非关键装饰，必要时保留折叠入口；不要遮挡选定落点和可交互对象。

## 2. 顶部入口与二级菜单的信息架构

### 2.1 默认一级入口：两枚

**A. `物品/角色`（背包图标）**：进入已有统一容器，内部按页签切换：

- 装备/角色：人物外观、六装备槽、属性与状态。
- 随身物品：16 格网格、类别筛选、物品详情、合法动作/合法目标。
- 已穿戴物品在装备槽展示，不再重复占普通背包格；已装备负重规则不变。
- 两页签是同一个容器的内部导航，**不得再把角色作为与背包同级的第三个常驻一级图标**。

**B. `更多`（菜单图标）**：展开游戏内的**二级覆盖菜单**，按实际已实现功能提供以下分组：

- **记录**：完整日志、图鉴、现有地图与设施信息。
- **游戏**：存档/读取、重放/回到游戏、新游戏（危险操作二次确认）。
- **设置**：音量、画面质量、UI 缩放、语言、帮助与操作说明。

没有完成的功能不要显示为可用按钮，也不要塞入若干空白三级界面。一级更多菜单首次展开可以是紧凑图标/短词清单，完整功能在必要时进入二级/三级内容层；尽量控制常用功能的点击深度。

### 2.2 菜单打开与关闭

- 主世界点击 `🎒` → 游戏内背包/角色覆盖层；点击 `☰` → 游戏内二级菜单。游戏世界仍作为背景渲染，可按可读性进行暗化或轻微模糊。
- 展开菜单后**世界交互暂停接受**，但世界时钟本来也在无动作时停止，不需要显示“暂停/继续”按钮。恢复画面只须关闭覆盖层。
- Escape、手柄取消、游戏内返回箭头统一表示“退到上一层”；退完所有层后回到世界。
- 用户点击模态面板外时，若允许关闭，**仅关闭，不把同一 pointerup/click 继续提交为地面移动或跳跃**。
- 主菜单切换到日志、设置等应有可返回的导航历史，不应反复打开嵌套的 HTML/Vue 侧栏。
- `?ui=legacy`、`?ui=buttons` 可以保留给回归/开发，不计入正式玩家界面审美验收。

## 3. 左上短日志与成功操作后的反馈契约

### 3.1 日志来源和更新

- 日志取自现有公开事件/`journal` 投影；**按时间顺序展示最新 2–3 条**。同一动作衍生多条记录时按可理解的显示规则去重或聚合，不得篡改游戏真实事件。
- 若已接受操作确实没有能被玩家观察到的事件，允许新增**不泄露隐藏性质**的可见操作回执，如“使用了未鉴定药剂；暂无明显变化”，不可伪造治疗、伤害或真实物品身份。
- 日志保持可见，不因 UI 面板开合而丢失；成功回世界后至少最近一次操作结果可立即阅读。设置适合中文与英文的换行/省略规则。
- 点击**实际短日志区域**打开既有 `CanvasMenus` 的完整 `journal`；列表保留阅读位置。仅阅读、滚动、关闭不消耗 tick/revision。状态条非交互余白不应该占用大热区。
- 操作无法执行的即时原因属于临时 `toast / intent hint`，可以靠近日志显示，但必须与正式行动日志有视觉与数据区分，不能假装命令已成功。

### 3.2 物品操作状态机（覆盖 M26 旧决策）

```text
世界 → 背包/角色 → 物品详情 → 选择操作 → 目标/确认
                                   │
              ┌────────────────────┼───────────────────┐
              │                    │                   │
       正式接受并完成          规则拒绝/失败       主动取消
              │                    │                   │
       清理残留目标状态       保留详情/目标和原因  退回上一层
              │                    │                   │
         返回游戏世界         不多扣任何额外时间    0 tick
              │
       场景动画+状态+短日志
```

- 被正式接受并完成的：穿戴、卸下、饮用、阅读、投掷、施法/法杖、应用、丢弃、使用工具、通过设施处理背包物品等，**无论道具是否被消耗**均回世界。笔记编辑、查看详情、分类切换等非游戏行动不属于此条。
- `commit` 不能把 `result === undefined` 直接当作“成功”关闭全部页面；须等正式提交回执，核对 `accepted`、`revision` 和状态同步。失败保持可重新尝试的上下文，不能显示“成功”通知。
- 操作成功后清理 `targetWorld`、合法目标选择、世界瞄准、上次菜单焦点、长按/悬停临时状态；不能残留会导致下一次点场景重复投掷的可执行 offer。
- 展示角色动作可以在菜单关闭后继续播放，但**动画帧不决定规则效果或额外推进时钟**。如果操作带动画，应该保证用户在首个可见主画面帧就能观察日志或明确的动作反馈。
- 连续使用若确有需求，由玩家主动重新打开物品界面；当前发行不默认保留详情作为多次使用模式。
- 状态因拒绝或外部更新而改变时，合法目标必须重新查询，避免使用过期的 `revision` 或不再存在的物品对象。

### 3.3 设施操作与上述规则一致

营火、祭坛、泉水、商人、机关等的合法性和详情仍按 M32/M33 的统一查询结构处理。**设施正式成功执行后返回世界**；只是查看说明、悬停/长按、浏览商品、选择加工物品不回世界；失败/取消保持应有的导航关系。

## 4. M32：优先修正输入歧义 + 覆盖式 HUD

### M32-01：移动与跳跃的屏幕意图消歧（P0）

已核查的 M31 代码问题：`src/room/scene-hit-test.ts` 的 `groundHit()` 对地面点击限制在 `floorY ±0.55`，跳跃空中候选从 `floorY +0.85` 开始，存在 0.55–0.85 空白带；`src/alpha2/Game.vue` 的 `worldClick()` 会优先处理跳跃候选并可能静默退场。

- 建立统一公开 `WorldPointerIntent`，让普通点击优先获得正常移动；**明显高处 + 有效跳跃目标**才触发 1–2 格跳跃。
- 点击到目标下方、地面和地面附近的可行连续区域时，能够可靠发起移动；视口与镜头变化不出现死区。
- 无效跳跃必须提示公开原因；不要把明确选择的高风险跳跃偷偷改成普通行走，但也不要把正常远程移动点误判为跳跃。
- 改变 UI 输入划分时一同更新 `CanvasInputRouter` 的热区层级：**打开菜单层 > 真实右上入口/日志框 > 世界实体候选 > 地面/跳跃**。非交互状态图形、透明画布位置不应额外拦截地面点击。
- 悬停/指向显示移动、跳跃、攻击或交互的预览，并仅使用公开状态。

### M32-02：寻路中断理由（P1）

`src/interaction/intent.ts` 中路径失败或遇危险时会 `cancel()` 而不提示。改为有结构化的公开原因：可见敌人、已发现危险、门锁、障碍、目标不可达、临时状态失效。短暂反馈可以位于左侧日志附近，但不伪造已提交的日志记录。不可泄露隐藏陷阱。

### M32-03：营火及现有设施的有意义动作（P1）

`src/core/action-query4.ts` 的旧营火候选仅按食物类别展示，已有局部规则复现可对已烹饪干粮再扣 **12 tick** 而无收益。优先在 Alpha5 专属能力查询/展示层剔除无收益项，保持旧身份规则语义；若要改正式规则接受条件另行版本化。

- 点击营火 → 设施简明详情 → 仅显示确有加工意义的食物 → 选物/确认；没有合法食物说明原因。
- 明确区分安全 `campfire` 与伤害性的 `hazard`，名称/形体/图标/行动提示不能混淆。
- 商人、泉水、祭坛、箱子等先说明设施与行动，再进入合法对象选择；不得把所有物品平铺成无限长度的一级操作菜单。

### M32-04：左上状态与短日志（P1）

替换 `src/game-ui/native-ui.ts` 中 `minimalHud()` 的**整屏顶部背景**与原 `hud()` 的**全宽顶栏**，只用局部悬浮绘制状态；其下放短日志，点击区域严格跟随可见日志面板。利用既有 `src/game-ui/menus.ts` 的 journal 页，不造第二套记录存储。

### M32-05：右上两枚入口与二级菜单（P1）

将目前 `minimalHud()` 在画面**底部绘制的 bag/aux/assist 三枚宽按钮**替换为右上 `[物品/角色] [更多]` 两枚轻量图标；`assist` 如需保留放在“更多→辅助/操作”或配置项下，而非默认一级。明确 `native-ui.ts`、`menus.ts` 和游戏输入层的开合、焦点、热区、返回层级。

### M32-06：操作成功返回世界（P1）

## 8. 代码接入位置与并行边界（核对 M31 源码）

| 模块 | 现有职责 / 已核实事实 | 计划改造 |
|---|---|---|
| `src/game-ui/native-ui.ts` | `minimalHud()` 当前全宽 64px 顶部暗条 + 底部 `bag/aux/assist` 宽按钮；`hud()` 使用全宽 82px 顶栏 | 全画幅覆盖式双角 HUD、短日志、右上两图标、明确可见热区、瞄准态收缩 |
| `src/game-ui/menus.ts` | `CanvasMenus` 已有 `menu` 与 `journal`；`ItemInteraction.commit()` 成功后按动作继续停详情、回背包或角色页 | 统一菜单入口与导航；正式接受后世界返回；拒绝留详情；既有完整日志复用 |
| `src/game-ui/input.ts` | `CanvasInputRouter` 统一输入区域与世界回调 | 顶部两枚图标和短日志的精确矩形、层级消费、指针取消/键盘/手柄导航 |
| `src/game-ui/layout.ts` | 装备/物品布局计算 | 统一容器、窄屏缩放、安全区域及视口避让 |
| `src/alpha2/Game.vue` | 世界与面板路由、`worldClick()`、`openPanel()`/`closePanel()`、`nativeUpdate()` | UI/世界互斥边界、聚焦恢复、操作回执、点击消歧与历史身份隔离 |
| `src/room/scene-hit-test.ts` | 世界候选、地面命中、跳跃候选、物体代理命中 | 地面连续区与高跳跃消歧、阻挡透明大范围点击 |
| `src/interaction/intent.ts` | 移动意图连续执行和中止 | 结构化中断理由、禁用行动原因 |
| `src/core/alpha5-query.ts`（若现有文件名不同以项目实际为准） | Alpha5 公开操作能力专属适配点 | 营火候选过滤、设施文本，不更改历史旧核心语义 |

**建议开发顺序**：先冻结 `HudLayout`（绘制矩形、实际互动矩形、世界空间碰撞检查）、`MenuNavigation`（world → 一级 → 二级 → 返回）、`ActionCompletion`（accepted/declined/cancelled）的最小合同，然后按输入/交互、HUD/菜单、设施能力三个工作包并行。**同一 `native-ui.ts` / `Game.vue` 不建议多个执行者并发修改**；集成者最后统一命中顺序和事件生命周期。

示意接口（仅为规划，不要求直接复制名称）：

```ts
type HudLayout = {
  status: Rect;            // 仅绘制，非交互，不自动阻挡世界
  shortJournal: Rect;      // 可见且可点击的日志区域
  inventoryIcon: Rect;     // 顶部右侧入口一
  moreIcon: Rect;          // 顶部右侧入口二
  visibleSafeRects: Rect[];
};

type MenuNavigation =
  | { kind: 'world' }
  | { kind: 'inventory'; tab: 'equipment' | 'bag' }
  | { kind: 'more'; page: 'root' | 'records' | 'game' | 'settings' }
  | { kind: 'journal'; returnTo: 'world' | 'more' }
  | { kind: 'item-detail'; itemId: number; origin: 'bag' | 'equipment' }
  | { kind: 'target'; itemId: number; actionId: string };

type ActionCompletion =
  | { kind: 'accepted'; revision: number }
  | { kind: 'rejected'; publicReason?: string }
  | { kind: 'cancelled' };
```

真正的屏幕矩形 `Rect` 必须按布局重新生成与尺寸变化保持一致，渲染和输入消费不能各算一套硬编码区域。 `visibleSafeRects` 表示可交互的实际图标/日志区域（名称可调整），非交互的状态衬底不应被登记为阻挡区域。

## 11. 资料出处与区分

**来自本次源包与上一轮审查的已核查事实**：`native-ui.ts` 的 full-width HUD 与底部三按钮、`menus.ts` 的已有 journal/menu、操作成功后不统一返回世界的当前导航、`Game.vue` 的输入调度、`scene-hit-test.ts` 地面/跳跃阈值、营火重复烹饪已复现。这些均为**M31 现状**，不是新功能已实现。

**用户本轮明确提出的设计要求**：左上状态和短日志、右上精简入口、二级菜单、全部 UI **覆盖在游戏场景上方**，优先利用上方天花板和上层梯子等低操作密度区域，而不是占用左右两栏；成功物品操作结束后回世界。

**设计补充（提案，不等于 WazHack 官方逐像素规格）**：两枚默认入口、容器内部双页签、HUD 实际热区、动态避让、展示行数、提示/回执层级、专门的开发接口及 M32–M35 分配。WazHack 官方操作说明可作为“直接点击地面/怪物/物品/门、点击较高处跳跃”的参考：<https://www.wazhack.com/help/controls.html>。本文没有主张该原作在所有设备上精确采用两枚右上图标。

**建议基线结论**：M31 保留作为功能 Beta 1；M32 先解决误触、营火候选与 HUD 结构，M33 再统一设施展示，M34 增加有组合深度的原创生态，M35 用精简、变更驱动的验证发布 Beta 2。

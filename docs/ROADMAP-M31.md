# 《星落远征》M26 RC1 验收复核与 M27–M31 开发路线图

> 2026-10-13 · 基线 `fallen-star-0.26.0-rc.1-source.zip` / `alpha4-1`  
> 性质：**本次独立源码及核心运行复核 + 后续开发设计**。尚未对现有项目实施 M27 代码变更。

## 0. 执行结论

1. **M26 主要功能可验收**。统一角色/背包、无伪暂停、操作后保留上下文、双向梯子、地面视觉堆叠/选择性拾取、装备不占普通格和新的资源生成在源码中均有真实实现；不需为了进入新阶段再次重跑全部旧浏览器、旧9000自然路线或全部历史存档。
2. **开始跳跃与内容填充**，不再继续堆叠 UI 验收阶段。优先构建“主动跳跃 → 越过危险格 → 正确落地/触发敌人 → 可视动画和输入”的完整闭环，再利用它开发可探索地形与新生态。
3. **测试改为变更驱动的精简门禁**。关键纯规则小测试、一次自然流程、一次真实浏览器操作和正式构建为每个交付的默认标准。长期数值平衡、跨旧版本全量存档、全机型浏览器矩阵、数千种子都改为**发布时 / 规则大改时 / 发现明显问题时**触发，不作为阶段固定工作。
4. 继续保留已存在的潜在问题台账（软件渲染长尾、JS堆增长、真机设备空缺），**有实际复现或变更触及相关模块时才专项排障**，不应因此阻断新内容。

## 3. M27：正式跳跃系统（优先P0）

### 3.1 范围和语义：保守可玩的第一版

- **仍采用现有 `(floor, x)` 整数逻辑地图**；玩家视觉上有完整起跳、空中、落地动作，但在规则层将跳跃作为**一次原子命令**，不能把画面中每帧当作逻辑步进。
- 新规则身份建议 `alpha5-1`、新入口 `alpha5.html`、独立保存键；`alpha4-1` 全部原样保留。新增身份将改动 `World/Command/Scenario/Session` 分派、版本化内容摘要、公开查询和黄金档。建议 `a5:jump:<targetX>`（同层）；不在这阶段加入三维自由移动/无限跳跃。
- 第一版只允许**同一层、起点可见、目标在1–2逻辑格内**且落地点可站立。建议基础2格跳跃消耗 **18 tick（待固定夹具验证）**，而正常走两格耗20 tick；避免跳跃成为始终优于步行的免费高速移动。
- 跳跃**中途经过**的陷阱、火区不按地面接触处理；**落地点**正常处理 `hazard2`。由规则先判定起跳和落点是否有效，再推进一次对应tick和敌人时序。第一次只设计“越过危险格”，**不支持跳过关门、锁门、墙体或占位生物**，不跨楼层，不越过实体障碍。
- 不在跳跃中忽略敌人的正常时钟：敌人仍随完整成本行动；当敌人恰好在落点占位、规则状态变化或终点非法时，拒绝/中断的含义必须明确。**拒绝动作零成本、零RNG变化、零状态变化**。
- 异常状态交互（睡眠、混乱、负重、束缚）必须由公开能力查询明确控制。第一版可规定“睡眠/束缚不能跳；混乱按既有系统确定性处理或直接禁用”，不要先加入没有完整模型的随机摔伤系统。
- **安全自动寻路不默认跳跃**；玩家显式点击空中的目标或按跳跃操作才允许越过陷阱。未来可在路线规划中加入“需要玩家确认的跨越”而不是暗中跨越未知危险。

### 3.2 输入与可视反馈

- 鼠标/触屏：在当前楼层地面上方、对应可见目标位置点击，显示短弧线预览及落点阴影；确定合法时提交 `jump`。**需要区别“点击高处起跳”与“点当前层附近的梯子上段”**：真实梯子命中与门/怪命中优先于空气跳跃；空中区需独立命中区，不要扩大地面命中框。
- 键盘：默认 `J` 可开启跳跃目标模式，再用左右选择1–2格落点并确认；或提供 `Shift+方向` 作为快捷方式（首版只选一种默认方案，允许设置）。不能覆盖现有 `Space=攻击`。
- 手柄：游戏世界内 A 可发起跳跃；菜单内 A 继续确认。暂停/失焦/转焦取消待提交跳跃，不应导致旧按键回放。
- 游戏画布中显示抛物线式跃起、收腿/伸腿、着地回稳，影子沿地面前进。优先使用已有23骨骼角色和动作调度接口，必要时制作一个可复用的 `jump` 动作剪辑；**动画不写游戏机械坐标**。落地点与实际命令状态必须一致。
- 不应新增常驻大号“跳跃按钮”；触控保持场景直点为主，陌生玩家首次发现可用轻量教学提示。

### 3.3 代码落点

- 规则：`src/core/alpha4.ts` 当前只分流Alpha3投掷与Alpha4基础动作；新增 `alpha5` **薄分派层**优先处理 `a5:jump:`，其余调用原有 Alpha4 行为。处理跳跃时重用 `advance2` / `hazard2` / `walk2` / `enemyAt2` 等纯函数，避免把整个Alpha4命令处理器再复制一遍。
- 会话：`src/core/types.ts`、`src/session/session.ts` 加一个新身份、命令解析与新黄金；旧接口不能写入新身份分支。
- 公共查询/意图：`src/core/action-query*.ts`、`src/interaction/intent.ts`、`src/room/scene-hit-test.ts` 返回合法落点与公开不可执行原因；禁止通过高亮未知陷阱而泄露隐藏设施。
- 动画：`src/room/presentation.ts`、`src/room/renderer.ts`、`src/character-lab/types.ts`、`src/visual/motions/*`、角色clip管线加纯表现 `jump`。
- 文案/教学：`src/alpha2/i18n.ts` 等活动入口提示移除“没有跳跃”，只对新规则身份显示新提示；旧入口保持历史描述。

### 3.4 M27验收门槛（约12–20个有意义的专项断言，而非整套重跑）

1. 有效1格/2格起跳；不可见/过远/跨层/封闭门/敌人占位/非法状态均正确拒绝。
2. 中途陷阱不触发，落点陷阱触发；普通步行仍保持原陷阱机制；单次命令恰好消耗一个确定时间成本。
3. 不输入时模拟静止；动画可暂停/中断，但不追加命令。相同seed+正式命令可得到完全一致的结局摘要。
4. **1条**完整自然跳跃→越陷阱→落地→拾取→继续探索场景浏览器测试；另有**1条**旧alpha4黄金档能加载的轻量烟测即可，不逐个执行全部历史黄金。
5. 真正有跃起动作、影子和着地动作，测试连续观察首/中/尾三关键帧；不会使用“瞬间蹲下”替代。

## 4. M28：将跳跃变成有意义的关卡能力（P0/P1）

只有跳跃动画而没有需要跳跃的地点会变成累赘。因此M28同步增加**小而完整**的新关卡模板：

- **露出的陷阱带**：通路可直接走但有危险，主动跳跃可安全避过1格危险区；其他路径可搜索/拆除或承受伤害。不能强迫每个玩家跳跃。
- **低矮障碍与压迫地形**：第一版仍没有高度平台和自由落差；可使用阻挡格、跳跃可跨过的独立障碍标签，配一个防止穿墙的碰撞类型。
- **地面环境组合**：火区+水/寒冰、毒性陷阱+抗毒、长通路+远程敌人；为不同装备提供不同解决路径。
- **角色状态边界**：悬浮可越过地面危险；负重/减速如要影响跳跃，先提交清晰规则定义，再实现。
- **地牢可视地形必须与实际可通行性一致**，不能在图片中画出可站立的平台，但逻辑仍只有单一水平走廊。若要真正添加高低平台、坑、掉落和层内纵向路线，应作为新的**独立地图拓扑扩展**留给M30之后，不能夹在简单跳跃任务中偷渡。

验收以4种种子和少量“通过/被拒/绕行”的性质测试为主；做一次浏览器完整闭环。暂不开展数千局自动平衡。

## 5. M29：第一批内容生态填充（与M27晚期可并行）

现有：45个物品规则定义、12种怪物、8类设施、6层×3连续片段、3个起始配装；45外观对应135件三LOD GLB。后续应强调“产生不同的探索决策”，而非单纯追数量。

建议按**三个主题生态包**生产，而不是一次性加百种同质物品：

| 生态包 | 主要场景 | 怪物（建议原创） | 设施/环境 | 道具互动与决策 |
|---|---|---|---|---|
| 腐菌矿穴 | 菌落/湿矿/腐蚀 | 孢子虫、菌伞守卫、拾腐者 | 孢子雾、菌巢、潮湿地面 | 火焰清菌但可能引燃；水/抗毒/照明的不同用法 |
| 断层工坊 | 机关/废弃机械 | 巡逻构装体、维护蛛 | 压板、可跳越的低障碍、可修机关 | 锤击/酸液/解扣法杖对机关有不同价值 |
| 墓烬回廊 | 亡灵/余火 | 灰烬侍从、墓影、拾火者 | 火焰槽、封印碑、脆化门 | 银/光/冷元素与诅咒解除形成策略组合 |

建议第一批 **6–9种有行为区别的新怪物，3–5类新增设施/地形，8–12种可交互的新道具**，外加相关的少量环境模型与音效。数量是规划上限而非必须一次交付；每包先完成**1怪+1物+1设施的纵向闭环**再扩展。

**内容定义规范**：每个新条目至少包括 `id/zh/en`、可公开外观身份、深度区间、出现权重、独立3D模型/LOD或有据可查的共享变体、行为或效果注册、克制/反制途径、UI已知与未知描述、低成本专项夹具；若为新机制还应列出所有可作用对象、时序与失败语义。

**掉落与生成**：复用 `ALPHA4` 中已经实现的层预算、`encounterLootCap=2`、屏幕窗口约束和独立loot RNG；增加区域/生态预算及遭遇组合规则，而不是回退到随意均匀撒物品。确保不同区有特色，但新手路线仍可达，不再在同一格堆教学补给。

**素材原则**：继续使用原创45套物品独立模型的制作/审计流程；新内容必须保证地面、背包和装备预览身份一致。不要以纯重着色冒充不同物品，也不要因未鉴定外观泄露真实定义。

## 6. M30：系统互作与关卡内容整合

- 让新增怪物与设施、物品至少形成**两种不同的解题路径**，例如跳过陷阱 / 搜索拆除 / 用工具远程解除。
- 引入“区域预算 + 难度预算”的生成组合；相同深度可遇到不一样的情况，但不产生无法通关的必经阻塞。
- 对新道具提供本局鉴定、祝福/诅咒、商人定价、用途多样性；对新怪物明确意图与已有抗性/弱点，而非只靠提高HP。
- 先做完整可玩的两个区域包，第三个视实际成熟度补足。地牢最核心的乐趣是规则互动、风险选择和意外组合，不要求立刻追到WazHack原始道具数量。

## 7. M31：内容Beta试玩候选（轻量发布门禁）

交付完整独立网页源包、可启动运行包、变更清单、已知问题清单、一份代表性自然玩法录屏/截图与数值设计摘要。不要强行做数小时压力、多引擎全尺寸矩阵或1000/9000种子扫荡作为这个候选必备条件。

### 精简测试制度（从M27开始执行）

| 变更类型 | 默认必做 | 按条件触发（而非每轮强制） |
|---|---|---|
| 纯模型/文案/UI布局 | 类型检查、受影响UI的1–3条E2E、资源加载检查 | 全浏览器矩阵、所有历史存档、千局数值测试 |
| 新怪/物/设施数据 | 定义/引用/模型校验、每项正反例、1–3自然场景、生产构建 | 内容成批冻结后一次多策略模拟 |
| 新跳跃/规则动作 | 正反例与tick/RNG不变量、1条自然链、1条新黄金、当前旧身份的**轻量哨兵** | 历史命令回放全集、跨版本修复大回归（仅共享底座改变时） |
| 输入/相机/碰撞 | 1–3条实际浏览器交互，屏幕/目标坐标一致性检查 | 多设备/浏览器回归（特定引擎问题重现时） |
| 版本发布候选 | 独占类型检查+构建、全部**新增专项**、关键自然链、资源清单核对 | 完整旧回归、性能长测及批量平衡：正式Beta/大版本发布或风险证据触发 |

- **不删除历史测试**：只是取消每个中间阶段对它们的重复执行。CI可以分为`fast`、`changed`和手动`full`三个门禁。
- **旧档继承**：不再要求新版本跨身份导入旧档，也不每阶段跑8份黄金。只要求旧入口继续存在、不被有意覆盖；新增身份建立自己1份可回放黄金。真正改到共同会话/解释器或计划正式发版时，针对受影响历史身份回归。
- **数值平衡**：不在每个生态小步循环全量模拟；每完成一个生态包跑小样本探索验证可解性；M30/M31内容冻结后才进行一轮适度的多代理/多种子基线，再根据不合理死因做定点采样。胜率不是唯一指标，也不能把10种子、同类自动代理的高胜率当作合适的难度证明。
- **性能**：M26的泄漏/卡顿不应遗忘，但若新增资产导致帧率明显下降、绘制对象持续增长、JS内存出现单调陡增，则马上触发局部剖析；其余留在计划发布前的固定一次性能检查。
- **自动化流程必须报告明确范围**：仅写实际运行的测试数、设备和结果，保留首次失败，不把设计方案或模拟输入视为通过证据。

# 《星落远征》M26 交互、装备背包、梯子与地面物品系统专项开发计划

- 审查基线：`fallen-star-0.25.0-rc.2-source.zip`，M25 RC2 / Alpha 3；参考 `M25-ACCEPTANCE.md`、上一版 `Fallen_Star_M25_Review_and_M26-M30_Plan.md`
- 编制时间：2026-10-12
- 性质：**下一阶段开发设计与验收规范**，不是已经完成的实现报告
- 新要求来源：2026-10-12 人工试玩反馈；本文件以实际 M25 源码为基础定位改造点

## 0. 总体决策

**先改善操作循环，再扩张内容规模。** 把原计划 M26 的「输入兼容性」扩展为 M26-UX（逻辑与易用性）与 M26-DEV（设备可靠性）两个可并行方向。对历史确定性规则保持绝对兼容：纯 UI 和表现变更可保留 `alpha3-1`；改变背包占用、初始掉落与生成配比、新物理掉落规则等会影响模拟历史的变更必须进入独立规则身份（建议 `alpha4-1`），新档、黄金路线和基线统计独立建立。禁止静默替换旧 9000 配置结果或修改旧黄金存档。

核心体验原则：
1. **点击场景表达意图，点击物品打开情境化详情。** 世界移动不依赖专门交互按钮；操作项随物品类型、公开知识和当前状态筛选。
2. **世界无行动不推进**是模拟语义，不应显示误导性的“持续播放/暂停”切换。失焦应取消已按住的输入与尚未提交的行动，不应产生新的模拟 tick。
3. **角色已穿戴与背包携带物品可视上分区**，最终规则上装备不消耗普通背包格，仍计入负重；实际容量规则改动需要新身份。
4. **物品的真实规则坐标与渲染摆放分离**。可以显示三维自然堆叠，但不要让刚体、fps、图形碰撞改变回放和目标身份。
5. 任何合法操作信息只使用公开查询，不因 UI 优化泄露未鉴定物品的真实类别效果。

## 2. M26-UX-A：统一角色 / 装备 / 背包（优先级 P0）

### 2.1 单一角色管理界面

正式版只保留一个默认入口「角色与物品」（背包图标或角色头像二选一），内部统一布局：

- 左侧/上部：角色 3D 模型与 **6 个装备槽**：头、身、腿、主手、副手、护符；点击槽内物品进入同一详情页，可卸下、查看已知状态、与同槽候选比较。
- 右侧/下部：**普通背包网格**，仅显示未穿戴的携带物品；支持筛选：全部、可装备、消耗品、工具、任务物品。网格无需再出现当前穿戴件的第二份图标。
- 人物属性、抗性、状态、负重放在此界面中的“属性/状态”页签，不再另设功能等价的角色页面。
- 横屏双栏；窄屏切换人物/背包页签，二者共享导航栈与所选物品。
- 详情仅呈现对应类别：装备展示同槽差值和已知属性；法杖展示已知充能与使用；药水/卷轴/食物展示可公开辨识的效果、数量、重量、知识状态、操作，不展示无关的攻防差值。

### 2.2 装备不占普通背包格的**两阶段过渡**

A. `alpha3-1` 可立即安全实施 **可视投影去重**：人物装备仅出现在装备槽；背包网格过滤 `equipped` 物品。此时机械携带上限**暂时仍计算全部 owner=bag 物品**；必须如实写为“总携带 x/16（含已穿戴）”，不能谎称“未装备 x/16”是机械容量。

B. 正式设计采用 **装备不占普通背包槽、但计入总负重**；`alpha4-1` 将容量判断改为 `owned && !equipped` 项数，装备成功和卸下均要校验容量与来源，背包满时卸装必须给出明确处理（先释放格子、放入安全地面、取消；不能无声吞物），并考虑已装备被诅咒物品的卸装限制。选择容量扩张时须配合难度平衡对照。

**验收**：无视觉重复；装备 6 件、背包 16 格边界；从背包穿上与卸下不复制、不消失，物品实例 ID 和祝福/诅咒/鉴定状态一致；历史 Alpha 3 黄金档完全不变。

## 3. M26-UX-B：取消不必要的暂停与改善焦点恢复（P0）

- 直接交互主画面不再常驻“暂停/继续”，Esc / 手柄 Start 打开原生游戏菜单。菜单打开、动画进行或窗口失焦时停止接受新指令；没有待执行的连续模拟计时器。
- 浏览器 `blur` / `visibilitychange:hidden` 立即撤销 hold、拟执行的 intent、pointer capture、模拟手柄持续按键、音频播放与可能的未完成确认；已**提交**的正式命令不能回滚，但不得因旧 pointerup 再提交下一次。
- 页面恢复可显示瞬时「已返回游戏」提示并直接进入等待下一次**全新输入**的可操作状态；不出现必须点击“继续”的人工闸门。为了防误触，触发窗口重新激活的那一次 tap/click 只负责聚焦而不执行移动或拾取；新的 pointerdown/keydown 才接受操作。
- 若有独立演出、过场、动作序列需跳过/暂停，使用演出控制状态而不是玩家世界时钟“播放按钮”。旧 `?ui=buttons` / `?ui=legacy` 入口保留既有行为作为回归对照。

**验收**：每一种 blur、tab 切换、锁屏恢复、`pointercancel`、手柄断联、菜单进出都断言 **tick、revision、archive 无意外变化**；恢复后首次明确新操作只提交一次；不发生隐式按键重放；无需点 Resume。

## 4. M26-UX-C：情境化物品详情与操作后导航（P0）

### 4.1 不应简单按物品类别硬编码隐藏未知功能

公开 offer 仍由 `queryActionOffers` / `queryTargets` 给出；详情 renderer 使用类别 + **公开已知知识** 决定信息区域。对于未鉴定物品只显示玩家目前能合理知道的信息，不通过“比较可用/不可用”反推隐藏实际效果。

- 武器、护甲、护符：有可比较槽位时展示 **同槽比较**，优先提供最终已知装备影响；未知词条标注 `?`，不默认以未知值 0 计算。
- 药水、食物、卷轴、法杖、工具：默认无“装备属性比较”。法杖如支持装备也只能展示该物品真正相关的已知属性。
- 操作详情按 `inspect/use/apply/equip/unequip/drop/throw` 等公开能力构建，不出现无意义按钮；成功提示和合法候选就地反馈。

### 4.2 明确定义「操作完成之后回哪里」

状态机：`BagGrid -> ItemDetail -> (SelectBagTarget | AimWorld | Confirm) -> ActionResult -> ItemDetail/BagGrid/World`。

- **非消耗且仍存在**（如多充能法杖、可重复工具）：成功后默认返回 **同一物品详情**，保留选中项与模型预览，刷新 charges、状态与 offers。
- **多件消耗品且还有同一堆/同一实例**：停留在当前物品详情，提供再次使用入口；使用计数同步更新。
- **完全消耗/已丢下/已出售/离开背包**：回到背包，并把焦点移到原格最近存在的物品，不跳回第一格。
- **装备切换**：停留在角色/装备页且当前槽位高亮，展示变化后的模型与合法操作。
- **投掷世界落点**：确认后回到来源详情（若仍拥有），否则回来源背包页；世界瞄准时允许取消并回到原详情、之前选中的操作。
- **失败或部分完成**：保留上一步上下文，显示公开原因；规则未接受时所有模拟数据与背包导航状态必须一致。
- 单次 use 的机械提交完成后，视图 revision 会刷新：应把 **导航栈和显示选中 ID** 与短命令的合法 offer 快照分离，先做结果检测，再重新查询最新公开 offer；不可直接沿用旧 revision 的可执行 command。

**验收**：覆盖使用不消耗/消耗一件/最后一件/多充能/装备/投掷/使用失败/取消/遭到危险中断；确认后不会自动坠回背包首页。

## 5. M26-UX-D：上下梯子一致的场景点击（P0）

- 不能只把上下梯当作一个中心点。将 **实际连通的梯子边** 显式投影为两个可点击区域或一个区域中的方向选择（参考 `LadderEdge {linkId, fromFloor, toFloor, x}`）。
- 按屏幕空间建立梯子上段、下段准确命中；点击上段向上、下段向下。如果场景投影或触控区域重叠，显示只有合法方向的轻量情境提示，而不是执行错误方向。
- 已在梯口且下层未探索：**点击看得见的梯子下段**是针对物理梯子的明确授权，可以下行一次，不能强制要求下层 `explored` 里先有目的格；但不得允许直接点击任意黑暗地下单元进行自动路径规划。
- 不在梯口时点击梯子：走到连通的梯口，若遇到敌人、未解锁门或危害则按 M25 意图规则中断；安全后按明确选择跨层一次。原 `up/down` 命令、时间成本与动画仍由真实规则控制。
- 改进渲染：梯级应在相邻两层具有清晰的视觉贯通，点击反馈箭头位于目标楼层而非统一浮在当前层。

**验收**：顶层向下、中间层双向、底层向上、未探索新层、安全/敌人阻挡、镜头边缘、触屏命中、操作取消，各配置记录完整档及每次 tick；不能只测试方向键攀爬。

## 6. M26-UX-E：地面物品堆呈现、命中与拾取（P0/P1）

### 6.1 先改地图生成，减少不合理的拥挤（影响规则，新身份）

当前 `src/core/alpha2-map.ts`：每层固定 `renewal @x3 + ration @x4 + random @x8/16/27`；入口另外 `water/venom/cinder/latch` **四件同时生成在 floor0/x6**。

- 原先教学资源移到首层多个相邻的可拾取位置，或使用一个新手储物容器/分次奖励，避免固定测试堆在同一格。
- 在 `alpha4-1` 新地图生成中引入 `lootBudgetByDepth`、`encounterLootCap`、`maxVisibleLooseItemsPerScreen` 与容器/敌人掉落分布权重；新手保底以「可解决的资源场景」保证，而不是每层机械地撒同样的补给。
- 保留少量有意义的多件物品堆，例如击败精英后遗物散落、商人遗落物、宝箱爆出，以测试拾取表现。
- 生成配额以实验台统计和固定种子检查验证；**不要仅减少所有掉率**，应结合消耗品供需、各职业胜率和可解性做配对测试。

### 6.2 先以确定性“视觉物理”实现自然堆叠（无规则变更）

提出渲染层接口：

```ts
interface GroundPileVisual {
  cell: { floor: number; x: number };
  members: Array<{
    itemId: number;
    assetId: string;           // 公开外观身份，不泄露未鉴定定义
    pose: { x: number; y: number; z: number; angle: number; scale: number };
    selectableBounds: { /* screen or projected 3D bounds */ };
  }>;
}
```

- 每个逻辑 `floor/x` 的物品是一个 **GroundPile**；选用模型公共边界、底面接触、单元格内前后深度和小幅水平错位，做 **碰撞简化的稳定摆放**。剑平放、背包倾靠、瓶子直立/小角度倾斜，所有模型遵守地面接触和互相遮挡上限。
- `pose` 可由公开 item ID、可见外观、堆中排序决定；无随机帧仿真、无网络/设备物理差异，存读档或回放在同状态得到同一堆姿态；同一物品拾起后相邻模型可平滑归位，但不推进游戏时钟。
- 模型不应伸入墙内、梯子通道、开门行程或角色的交互接触轨迹。超出单格可辨认能力时展示「物品堆 ×N」标记，进入地面物品选择器，不无限增高模型。
- **不建议第一版引入实时刚体堆叠引擎**：如果未来要动态抛掷和落地弹跳，只在视觉表现期运行受限制的动力学，完成后固定最终姿态，并把机械落点视为规则结算决定的坐标。

### 6.3 保证“看得见”就能“点得到”

- 目前 `scene-hit-test.ts` 对共格物品创建中心和大小都相同的代理，排序时相同优先级，天然优先命中同一条。改为返回 **候选集合**（例如 `WorldHitCandidates`），其投影命中区与上述各物品的视觉 `pose` 绑定。
- 有暴露且命中唯一的模型时：单击拾取此物品（保持原 `take:itemId` 规则）。
- 多模型重叠、被挡或触摸不易精准选择时：点击/短暂停留弹出就近的 **地面物品选择浮层**，每项显示可辨外观缩略图、玩家公开知道的名称/状态；点击单项拾取，长按可打开只读详情。提供显式“全拾取”但不默认触发，逐项检查背包容量与安全条件。
- 鼠标 Hover：高亮真实对应模型，显示名称/重量/已知状态及同格数；触屏长按：相同功能，抬手默认不拾取；单击命中有歧义时进入候选列表而不随机拿第一件。键盘/手柄通过目标循环与确认完成同样的逻辑。
- 提示必须避免未鉴定信息泄漏；所选对象从头到尾使用稳定的 itemId 而不是按数组序号。

**验收**：1 / 2 / 4 / 8 件同格物品，分别测试模型可辨认率、屏幕命中集合、候选高亮、单取、剩余物位置更新、背包已满、敌人打断、取完归空、存档重放、不同分辨率和画质档、手机长按。自动 E2E 点击某一露出模型后取得 **指定 ID**，而非“任一物品”。

## 8. 建议正式验收指标

1. 直接模式 HUD：角色/背包只有一个入口；普通探索不显示 Pause/Resume；可不点击 Resume 完成“失焦→恢复→新行动”。
2. 背包：装备栏与携带列表视图无 ID 重复；旧规则容量文案诚实；新身份中已穿戴装备不消耗格子，卸装满格流程明确；45 种物品按已知类别检查详情和合法动作，不出现非装备默认攻防比较。
3. 持续使用：药水、法杖、装备、卷轴、工具、投掷、失败和取消至少各有一个真实规则测试；可重复物品成功后保留详情选择，下一次合法目标由新 revision 查询。
4. 梯子：点击画面上段/下段各自执行相应 `up/down`，首次下楼允许未探索楼层的一次明确探索授权；取消与异常路径零额外命令。
5. 地面物品：每组 1/2/4/8 共格的可视模型，真实点击指定成员后只取该 ID；Hover 与触屏长按显示公开名称、堆内选择；模型分离且不强求各项完全无遮挡（超量有选择器）。
6. 规则保持：旧 `alpha3-1` 黄金档不变；规则变化只在 `alpha4-1`，建立新黄金档、1000 独立种子分布、不同配装/代理资源需求 A/B；自动追踪世界 tick、revision、archive、目标 ID 和渲染候选命中。
7. 设备：桌面 Chromium、Firefox、iOS Safari、Android Chromium、手柄输入逐项登记；没有真机不能写已通过。页面 / 软件渲染 / 测试用按钮旧入口保留独立回归。

## 9. 生产导向的 UI 路线示意

```
正常探索 ──点击角色/背包入口──> 角色与物品（单一入口）
                                        ├─ 人物预览 + 六装备槽
                                        ├─ 未穿戴背包格 + 分类筛选
                                        └─ 属性/抗性/状态页

物品格点击 ──> 对应类别详情 ──> 选择公开合法动作
                        │                 ├─ 自身/背包合法对象高亮
                        │                 └─ 游戏世界自由瞄准
                        └──结果确认 <──────┘
                               ├─ 仍拥有：原详情刷新
                               ├─ 不再拥有：背包邻近项
                               └─ 装备变动：人物/装备页

地面单件露出 ──点击──> 拾取指定 itemId
地面多件混叠 ──点击/长按──> 浮层列出公开可识别的成员 ──选择──> 拾取指定 itemId
上方梯段 / 下方梯段 ──点击──> 相应上/下意图（需遵守已知连通与打断）
```

# M16I 任务包：接口冻结、集成、风险与测试门禁

**角色**：集成负责人；不以任一执行者自检代替独立审查。  
**基线**：用户提供的 `fallen-star-0.15.0-alpha.2-source.zip`；若源码目录没有 Git 元数据，先记录真实基线/分发 hash，不杜撰 commit/远端分支。  
**接口冻结**：`ItemVisualSpec`、`appearanceKey`、`CanvasInputRouter`、`PresentationActionReceipt`、`MotionProfile`；允许后续兼容扩字段，不允许各工作组分别发明冲突版本。

## 集成顺序

1. 阅读所有任务包及源码合同，明确 UI 只读 PublicView 的安全字段。
2. 合并 M16C 的外观 registry 与 M16B 的背包 UI，检查实际模型在地面/背包/角色/商店一致。
3. 合并 M16A 的 CLI 和报告，不让测试代理或报告模块导入渲染器。
4. 连接真实可提交的拾取与开门/拉杆/箱子命令到动作收据与表现；不在渲染完成时再提交命令。
5. 跑项目现有 check、models、E2E、黄金存档；新增场景回归和手动截图检查，并报告所有未运行项目和原因。

## 失败与版本管理

- Pure presentation changes 不得改变 M15 的历史机械摘要；发现变化应定位为模拟污染并回退。
- 如果必须新增动作中间态或新游戏规则，先批准独立规则身份和存档键，保留旧档可恢复。不能悄悄修改 `alpha2-1`。
- 截图/视觉检查验证真实 GLB、真正的手/物接触和画布 UI，不得只用单测模拟声称美术完成。
- 如 CI 依赖不可安装，明确报告受阻，允许独立纯逻辑检查但不得声称全套通过。
- 记录资源许可证/来源和 hash；不自动部署或采购。

## 交付格式

- 代码变更说明和实际触及文件。
- 新接口与兼容条款。
- 已运行的命令、数量、设备环境、成功/失败与首次失败归因。
- UI/动作截图和资产完整性报告。
- 遗留问题、禁用/回退开关、明确下一阶段责任。

# 《星落远征》M21–M25 交互体验重构开发计划

**文档状态**：开发规划（未实施）  
**基线**：用户提交的 `fallen-star-0.20.0-rc.1-source.zip`，版本 `0.20.0-rc.1`，正式入口 `alpha2.html`  
**审查日期**：2026-10-12  
**目标**：将 M20 的“画布中绘制按钮的操作模型”迁移为“直接点击世界 + 物品详情 + 合法目标高亮 + 情境交互”。保留已完成的 3D 物品、美术动画、确定性核心和测试基础设施。

## 0. 审查依据、事实边界及公开参考

- 分发包 `source-release.json` 的 **387/387 项逐文件 SHA-256 与字节数验证通过**。`public/assets/items/` 实际包含 **135 个 GLB**；`node scripts/check-boundaries.mjs` 验证了 24 个模拟、内容和会话模块的无渲染边界。源码包未附带 `node_modules`；完整 `npm run check`、Vitest、Playwright、基于 Three.js 的模型审计**没有在本次环境独立重跑**。
- 项目自身 `docs/M20-ACCEPTANCE.md` 记录了 137/137 Vitest、94 项不同 E2E 用例经首轮与有限失败复测达到通过、9,000 配对模拟 trace 与 M17 基线一致。该报告明确保留了一次未复现的键盘时序问题、软件渲染长尾延迟、盾缘裁切和真机覆盖空白。不是“每次全套一次性全过”或本次独立验证。
- WazHack 官方 `https://www.wazhack.com/help/controls.html`：点击地面移动，点敌人攻击，点物品拾取，点友好生物互动，点门后方开门，点门把手关门；原作仍保留背包/施法/投掷等图标，移动端会切换紧凑工具图标。因此模仿的是**以世界点击为主、按需呈现工具**，不是虚构“原版从无任何按钮”。
- WazHack 操作还包含点击高于地面位置跳跃；**本项目既有规则明确不实现主动跳跃**，不可因直接模仿输入而悄悄添加跳跃能力。

## 2. 本次代码核实的具体交互缺陷

1. **主画面仍有常驻操作条**：`src/game-ui/native-ui.ts` 的 `hud()` 绘制了 `left/up/down/right/attack/interact/potion/wait` 八个按钮，以及施法、搜索和附近设施操作按钮。`src/game-ui/input.ts` 的命中检测只在 UI 热区矩形中处理 pointer，没有主场景实体拾取/点击导航回调。
2. **背包操作密集**：`native-ui.ts` 的 `bag()` 中，选中物品后在右侧 `detail` 矩形里绘制 `action:*` 的多按钮列表；执行时又用一个 `target` 按钮顺序循环目标，再按 `execute`。`menus.ts` 的物品详情页主要用于查阅，没有作为所有操作的统一入口。
3. **合法目标筛选与真实规则分离**：`native-ui.ts` 的 `targets(action)` 及 `Game.vue` 的 legacy `targetsFor()` 只按照 `TargetKind` 粗略过滤。例如 `throw` 把**所有设施**加入候选，`zap` 列出 self/enemy/facility，`read` 同时显示 self/item，`apply` 列出各种不能承受效果的物品。真正的拒绝条件却分散在 `src/core/alpha2-effects.ts` 的 `target2()`、`useItem2()`、`effect2()`（效果目标、类型、距离、状态、耐久、充能、同物品等）。这会造成“UI 允许选择、核心必然拒绝”。
4. **投掷还没有自由地面落点语义**：`src/core/alpha2.ts` 的 `a2:use` 命令只接受 `self` 或 e/i/f/d ID，不支持 `floor/x`；`useItem2` 只允许投向敌人或（药水的）设施。不能仅靠 UI 切换就实现“点画面任意合法落点”。
5. **开门已可独立提交，但尚未绑定意图**：当前 `left/right` 碰到关闭的门由 `walk2()` 返回 `blocked`，单独的 `door:<id>` 可开关门，`lever:<id>` 解锁；还没有“用户想继续前进 → 在碰撞之前自动开门/请求选择”的输入意图解析。
6. **公开外观和鉴定边界需要保护**：`publicItem2()` 为未知物品隐藏真名，但 `actions` 来自真实定义。下一版展示合法目标/操作理由时，必须避免因效果类型或差异化按钮直接暴露药水、卷轴和法杖隐藏效果。
7. **自动平衡不能被误读为难度合理**：项目记录的 9,000 配置中 8,969 胜、31 死主要证明代理/规则行为可重现，不足以证明真人难度适宜。操作易用性要依靠交互路径和失败率指标，难度仍依靠分层代理进行量化。

## 3. 最终体验规格：同一套意图，多种输入方法

### 3.1 世界直接操作（默认输入，优先）

| 玩家意图 | 鼠标 / 触屏 | 键盘 / 手柄保留 | 规则动作与时间 |
|---|---|---|---|
| 探索 | 点地面，朝可达位置自动逐步移动 | WASD / 左摇杆 | 逐次提交正式移动命令，保留每步时间 |
| 战斗 | 点可见怪物；无法直接攻击时可选择移动到攻击范围 | 方向撞敌/攻击快捷键 | 只用正式攻击/移动，不自动穿越危险区 |
| 拾取 | 点可见地面物品；若不在可拾范围先走近 | F / 可选游戏菜单 | 合法近距离才提交 `take:<id>` |
| 未锁的关闭门 | 点门后方、门本体，或持续前进至门前 | 朝门方向前进 | 自动提交原有 `door:<id>`，动画结束后再尝试继续移动 |
| 关门 | 点门把手/门扇可交互点 | 情境菜单 | 只在未被占据、当前可关时提交 |
| 锁门/门闩 | 点目标或移动受阻 | 情境面板 | 如果公开条件支持，显示解锁/使用杖/取消；不可强制无条件开门 |
| 多动作设施 | 点拉杆、宝箱、泉水、陷阱等 | 情境操作 | 对每个设施仅显示当前可尝试的动作，必要时要求确认 |
| 梯子 | 点梯子上/下的实际目标位置 | W/S | 逐步执行可达路径和真实爬梯动作，停止时不额外推进 tick |
| 远程道具 | 物品详情 → 投掷/施杖 → 画面瞄准合法对象/落点 | 键盘目标循环 / 确认 | 原有施杖继续作用于合法实体；自由落点投掷在新版规则中实现 |
| 对自身/物品使用 | 点击使用中道具 → 背包/装备槽高亮合法目标 | 可焦点导航 | 未确认前不消耗时间、充能或物品 |

主画面**默认不显示方向键、攻击键和设施操作键矩阵**；保留可访问的背包/角色/菜单入口和最小 HUD。触屏仍允许在“辅助操作”中选择显示方向盘/快捷按钮，作为可选辅助功能，不强制普通玩家使用。

### 3.2 背包与详情两级交互

- 第一层：人物模型、六个身体装备槽、16格背包；格内高辨识 3D 模型缩略图、堆叠/耐久/已知状态标记。**点击任意非空背包格或已装备槽，都进入统一物品详情页**。禁止常驻物品右侧的“穿戴、喝、读、投、丢...”按钮矩阵。
- 第二层详情：大号可旋转 3D 物品预览、按已知权限过滤的属性、耐久/重量、效果描述、装备比较以及一列可滚动的语义操作（如装备/卸下、使用、投掷、丢弃、查看/笔记）。操作为情境选项，不等于主场景常驻按钮。
- 选择无需目标的动作：必要确认后提交；需要目标的动作：**保持物品已选中的应用状态**，呈现可选合法对象。
- 指向背包或角色的动作：背包和六个装备槽中**高亮合法目标，灰化不可用项并可说明公开的原因**；自身为独立可选目标区域。确认后才提交单一正式命令。点击返回、Esc、切换物品、失焦、切换语言、存读档和回放应取消 pending，不扣游戏时间。
- 投掷/对场景施法：详情缩回角标，恢复可见世界；合法实体显示轮廓/标记，合法地面显示预计落点光标、射线/抛物线预览，明确“选择落点 · 取消”。键盘/手柄目标切换不依赖可见列表。UI 仅显示公开、确定的预测；不泄露随机隐藏命中/效果。
- 长按、拖拽可以是便捷操作，但不作为唯一方式；触屏长按 **绝不在抬起之前提交规则动作**。详情、目标页和主场景的操作语义保持一致。

### 3.3 情境选择与危险操作

- 默认自动：未上锁且无歧义的开门、点地面拾取、走向已知目标、明确点击怪物攻击。
- 必须询问：需要花费金币/生命的开箱方式；存在多个互斥设施操作；可能误伤友方；需要破坏/丢弃稀有物品；玩家点击锁门却有多种处理手段。
- 发生风险但符合传统 Roguelike 预期的普通行为（例如喝未鉴定药水）不应每次强制确认，可在首次提示或设置中调整。
- **不得用“移动受阻”作为所有交互的泛化触发器**：实体阻挡、门上锁、陷阱、高差、看不见的障碍，要分别判定，避免自动执行有害命令。

## 4. 正式技术边界与数据合同

### 4.1 Intent（意图）与 Command（机械命令）分层

```ts
// 提案：src/interaction/intent.ts；实际名称实施时在接口冻结表中确定。
type WorldIntent =
  | { type: 'move-to'; target: { floor: number; x: number } }
  | { type: 'activate'; entity: { kind: 'door' | 'facility' | 'ground-item' | 'enemy' | 'ladder'; id: number } }
  | { type: 'use-item'; itemId: number; action: string }
  | { type: 'select-target'; target: TargetRef }
  | { type: 'cancel' };

type TargetRef =
  | { type: 'self' }
  | { type: 'inventory-item'; itemId: number }
  | { type: 'equipment-slot'; slot: string }
  | { type: 'world-entity'; kind: 'enemy' | 'facility' | 'door'; id: number }
  | { type: 'world-cell'; floor: number; x: number };

interface PublicActionOffer {
  actionId: string;
  status: 'enabled' | 'disabled' | 'uncertain';
  publicReason?: string;
  targetMode: 'none' | 'self' | 'bag-item' | 'world-entity' | 'world-cell';
  requiresConfirmation: boolean;
}
```

解释：`WorldIntent` 是表现层暂态，**不可写入机械事件流替代正式命令**；每一次实际行动仍调用 `GameSession.submit(Command)`。路径自动化要逐步执行并在每次成功提交后重新读取公开视图和检查阻断；不得预先批量扣时间/随机数。

### 4.2 合法动作能力 API（关键架构）

新增唯一规则查询入口（名称建议 `queryActionOffers` / `queryTargets`），由纯规则层对当前机械状态**无副作用地**计算结构合法性，再导出信息过滤后的公共投影供 UI、自动代理和 AI 测试共用。禁止 UI 与 `Game.vue` 各写一套 `switch(action)`。

- 检查：物品拥有权、是否装备、剩余充能、射程和可见性、路径/遮挡、实体存活、设施使用状态、B/U/C 公开知识、物品材质/耐久、金币/背包空间、目标是否自身、同一物品作为源/目标、状态异常、动作形式与目标种类匹配。
- `enabled` 只表示**公开前提下可安全尝试提交**，不能承诺秘密效果成功；`disabled` 只在公开可证明不合法时使用；未知身份/随机效果的适用性显示为 `uncertain`，不得借规则内部真值向玩家泄露隐藏身份。
- 提供稳定的公开禁用理由，比如“超出射程 / 无法看见 / 目标不是装备 / 耐久已满 / 没有充能 / 不足金币 / 被诅咒无法卸下（仅已知时）”。对于未知条件提示“效果未知”，不得显示真实抗性/诅咒。
- 每份候选含 `revision`/可见状态版本，用户点确认时**复查并提交**。若世界已变化，应取消或要求重新确认，而不是投出已不存在的物品。
- 要求 `query*` 无 tick、revision、RNG、存档或日志副作用；不要用读取隐藏 `EFFECTS` 的结果直接生成未鉴定物品的确定目标列表。目标查询是**提示与筛选**，核心 `acceptAlpha2/acceptAlpha3` 仍为唯一结果裁判。
- 用表驱动和属性测试核对所有物品定义×动作×目标种类，并运行实际 `submit` 反例；不得只通过静态快照或屏幕截图判断合法。

### 4.3 场景命中测试与点击移动

在 `src/room/` 引入 `SceneHitTest`（Three.js `Raycaster` 或等价的正交投影拾取层），利用真实 `RoomRenderer.camera`、客户端 CSS 像素位置和当前视图建立实体命中优先级：UI 热区 > 模态选择 > 可见可交互实体 > 已知地面位置。地面物品 `GroundItem:<id>`、门、拉杆、敌人、梯子应有稳定 **公开** ID 与拾取代理网格，且不能命中战争迷雾内的隐藏对象。

- 同层路线：寻路在现有横向走廊上沿 x 前进，梯子通过已知连接点跨层；只能针对已发现路径规划。后续复杂图结构不在本轮强制范围。
- 逐步移动：每次正式动作后重新计算。敌人出现、伤害、陷阱触发、异常状态、背包满、障碍更改、角色死亡、点击新位置、打开菜单、失焦、保存/恢复、重放时应取消或打断自动前进。不能让一次触屏点击继续无警告地走进远处危险。
- 关闭门：点击门把手可关，点击门后地面通常开门前进；无把手点击或歧义时出现轻量情境选择。键盘撞未锁门也按相同“向前通行”意图执行，不能在移动方向改变/手指抬起后续走。
- `MotionInput` 可以复用“按住时逐步提交、busy 时等待”的保护逻辑，但路径点击需独立 `IntentExecutor`；`settle()`、页面切换、旧 pointerup 等必须清理旧意图，避免已发生过的重复行动问题。

### 4.4 自由落点投掷：明确需要新规则身份

当前 `a2:use:<id>:throw:<target>` 不支持地面格。新增世界落点不是纯 UI 变化：需要决定无目标时是否仍消耗道具、射程/遮挡、抛射物与敌人的优先碰撞、允许落点的格子、高度/楼层、掉落归属、友方/设施命中、无效果法杖投掷如何落地。**建议另立 `alpha3-1` 机械身份**（或遵循仓库维护者批准的版本命名），不要默改 `alpha2-1` 的历史 `Command`、黄金档与 `dungeon-descent.m15`。

提案命令可为 `a3:throw:<itemId>:<floor>:<x>`（实际接口冻结后决定）。落点先限定**当前楼层、已探索且可见的有效地面格**；禁止跳跃式跨层投掷。穿越门/墙按确定性射线判断碰撞，实体、设施先于地面，允许命中已公开可见对象。发射与落点判定只在模拟层进行；3D 抛物线、手臂动作、弹着特效只消费命令成功收据。新增自动代理只能通过新命令接口测试新版规则。

## 5. 里程碑：先可用，再加自由投掷

| 阶段 | 主题 | 改动重点 | 冻结与门禁 |
|---|---|---|---|
| **M21：公共能力与交互状态层** | 先减少“菜单选择必然失败” | 统一 `queryActionOffers/queryTargets`、信息过滤与错误提示；详情/目标选择状态机和输入事件优先级合同 | 全物品动作矩阵、无秘密泄露；查询零副作用；不改旧存档摘要 |
| **M22：场景点击与智能通行** | 去掉常驻移动/开门/拾取操作条 | `SceneHitTest`、点地导航、点敌攻击、点物拾取、门后自动开、门把手关门、梯子和情境设施菜单 | 10 场景交互任务可无操作条完成；阻断/危险中止；保留键盘和回退入口 |
| **M23：背包/装备详情与目标高亮** | 摒弃物品操作按钮栏 | 统一装备与物品详情页；合法背包/装备对象高亮；自身选择；多级返回；未鉴定信息保护 | 8 类物品动作端到端；鼠标/触摸/键盘可达；非法目标不可确认；取消不扣时间 |
| **M24：世界瞄准与自由落点投掷** | 在画面中精确选择目标 | 目标轮廓/落点准星/射程指示/遮挡；位置型新命令和抛射碰撞规则 | 新身份、独立存档；跨种子确定性命中/落地；投掷/撤销/失焦无双提交 |
| **M25：整合与 UX 回归** | 生产级直接操作体验 | 统一鼠标/触屏/键盘/手柄，删主画面强制按钮；改布局与新手提示；无渲染与真机验收 | 发布 RC2，旧回放零变化，新自然路线、设备与交互指标报告齐备 |

**依赖关系**：M21 能力合同应先冻结；M22 的场景点选与 M23 的详情视觉可以并行，但只能共享同一 ActionOffer/Intent 接口；M24 独立开发新版规则且不能改旧机械身份；M25 总集成。不推荐五阶段一口气直接合入主线。

## 6. 自动验收矩阵（重点任务必须编成可重复测试）

### 6.1 严格的机械与状态测试

1. **门**：右侧关闭未锁门，点击门后或持续右行时，先产生 `door:<id>`（原价 8 tick），动画结束后允许下一步 `right`（原价 10 tick）；点击取消/释放后不自动进入门。锁门不得自动打开或绕过；需明确、可取消的选项。没有目标的失败尝试不改变 tick/RNG/存档。
2. **门方向**：从两侧靠近，推/拉动画方向正确，关门时门格存在生物不允许执行。
3. **设施**：收费宝箱按现有规则金币/生命扣除一次；未确认关闭对话框前不得扣除。拉杆/陷阱/泉水仅展示本次可尝试的合法操作。
4. **导航**：长距离点击只提交一次一格的正式命令；遭遇新敌人、受到伤害、状态变化、越过楼层、存读/回放/失焦后安全停止；没有动作补交。
5. **物品**：45种真实定义及所有公开外观，至少覆盖 `drink/read/zap/throw/eat/apply/equip/unequip/drop` 的所有有效/无效目标族；已知的禁止条件不能列入可点击合法目标。
6. **鉴定安全**：同类别未鉴定物品即使真实效果不同，查询对同等公开属性返回相同能力信息；对比两份世界除了隐藏定义不同以外的公共投影，UI 不可辨真值。允许用户主动尝试未知的作用，不要求百分百成功。
7. **选择与取消**：双击、长按、拖离、pointercancel、旧 pointerup、切换面板、resize、读档、切语言、回放、WebGL context lost 等均不得重复提交；纯 UI 操作 tick/revision/RNG 不变。
8. **新投掷**：目标指向地面、敌人、设施、障碍边缘、超距、上下层、未探索区域、敌人中途移动等；显式定义碰撞先后次序，确保模型抛射轨迹与机械命中位置一致但不影响判定。
9. **历史兼容**：六份黄金档、原 M20 9,000 配对配置在只改 UI 的 M21–M23 中保持 trace/digest 完全相同；M24 新身份有单独黄金数据，不能混入原基线报告。
10. **性能/资源**：模型和缩略缓存复用，切换背包/世界/目标模式 100 次无需残留 GLB、texture、pointer listener；画布尺寸变化没有重影、盾牌预览不裁边。真实设备与软件渲染分别列报。

### 6.2 UX 目标与量化指标

- **默认没有常驻动作键条**：对正常探索、战斗、拾取、开门、关门、梯子、开箱、装备、饮药、投掷等核心流程都提供直点或对象上下文入口。
- **最多一个意图点击开启普通门**：点击门后目标无需先点击“开门”按钮；不要求每个连带真实行动只有一个机械命令。
- **合法目标零误导**：在已知公开条件下标为“可执行”的候选，测试中不能出现确定性规则拒绝；未知效果归“可尝试/未知”，拒绝原因不能泄露秘密。
- **取消零成本**：进入/退出物品详情、选择落点与情境对话不推进游戏时间。仅实际成功的世界动作扣时间。
- **中断零补交**：任一取消路径都不允许被延迟指针释放、动画完成、Promise resolve 或长按计时器补提交。
- **三尺寸 + 真实设备抽样**：1440×900、844×390、390×844 的浏览器门禁；至少一台真实触屏设备及一款非 Chromium 浏览器的兼容试验单独记录，不以模拟视口冒充真机验收。
- **人工角色改变**：人工主要检查是否符合直觉、是否易误触和美术可辨识度；不要求人工通过大量跑局测试平衡。

## 8. 最小纵向验收脚本

使用种子固定的两层片段场景。玩家在**不触碰旧动作按钮条**的情况下：

1. 点远处地面 → 角色逐格走近；途中碰上未上锁门 → 自动开门，保持分阶段门动画后通行；玩家点击取消时立即停止。
2. 点地上药瓶 → 走近并拾取；点背包图标 → 点药瓶进入独立详情（显示与地面同身份的 3D 图）。
3. 选“对其他物品使用” → 只高亮可尝试的装备或物品；点选并确认。没有目标时显示明确原因，不得提交无意义指令。
4. 选法杖 → 施杖 → 直接点击世界中的合法敌人/设施，不再通过菜单轮换名字；成功播放真实施杖与光束表现。
5. 选投掷物 → 游戏画面显示可选格与轨迹 → 点地面格确认 → 可见落点与机械结算一致，取消不耗 tick。
6. 点需要费用的宝箱 → 原生情境页选择支付/强开/取消，仅成功选择推进规则。
7. 打开装备栏 → 点已装备武器 → 物品详情 → 卸下或换装，角色模型、装备格、地面丢弃外观一致。
8. 保存、恢复、回放 → 无遗留待执行动作；重复上述路线与 golden trace 一致。

只有这条链在鼠标、触屏和键盘下均通过，才进入 M25 全面 UX 优化。

## 9. 版本与范围停止点

- M21–M23 属于 UI/意图层改造：优先重用现有命令以维护 `alpha2-1` 的历史机械不变性。若为达到目标必须改变机械规则，单独标为 M24 候选，不在 UI 阶段暗改。
- M24 的自由落点投掷和新的碰撞/目标语义，需要对规则、存档、回放、测试基线建立清晰的新版本。不承诺旧存档自动升级。
- 暂不扩职业、怪物与物品总量；暂不修改 45 模型资产体系，不增加实时战斗、主动跳跃或多人联机。
- 各阶段必须附源代码变更清单、自然命令 trace、受控边界测试、独立 UI 截图/视频、已知问题表。反例修复必须重跑原测试，不允许仅报告“已修复”。

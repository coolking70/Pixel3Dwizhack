2026-10-11：用户授权持续开发至 M10，仅核心方向、付费或发布等重大决策暂停。M06 是兼容基线，验收事实统一登记 STATUS.md。

完成状态：M07–M10 已于 2026-10-11 完成本地 Alpha 0.10.0-alpha.1 交付。七入口回归、自然通关、旧档兼容、硬件/软件渲染采样和分发包重复构建均有验证记录，详见 `STATUS.md`；真实手机、其他浏览器与真人难度反馈仍属于后续验收范围。

## 实施约束

- M06 expedition-1/commands 4 和三种更早规则身份保持原逻辑及内容摘要。先保存正式路线黄金档，再新增 Alpha 版本。新玩法不回写旧状态。
- M07 数据包采用项目骨架的受限 JSON 网格部件格式，包含原创实际角色、衣甲、武器模型和来源；不把这种导入称为任意 FBX/glTF 自动重定向。通用外部骨架仍须先转换到项目合同。
- 新状态由模拟唯一拥有，UI 只读公开视图、发送语义命令；动作表现、模型和帧率不驱动规则。衣甲遮罩和插槽由呈现层拥有。
- 新资产优先原创与现有 CC0 来源，不采购；不复制 WazHack 的资产、代码或数值表。接口只预留确有用途的能力。
- 保存、导入、回放保持完整历史验证；未知规则/内容明确拒绝，不静默迁移。
- 自动化设备模拟和软件 GPU 如实标注。无法接触真机时记录覆盖缺口，不伪造真机认证。独立审查未执行时明确区分作者自查。
- 不外部部署、购买或发送消息。完成本地可分享构建属于本次授权；实际对外发布需单独明确指令。

## 顺序与停止点

先完成 M07 的实际资产与战斗检查；再从冻结 M06 派生 Alpha 规则，在 M08/M09 中一并确定新身份，最后执行 M10 集成验收。每阶段完成后记录证据并继续，不以“计划已写好”或阶段性截图替代 M10 交付。重大产品选择才向用户提问；普通实现、缺陷修复和验证持续自主推进。

## M08/M09 具体规则合同

- 新 `alpha` 场景、`alpha-1` / commands 5，`alpha.html` 与独立存档键。在新局的首个命令选择先遣者（剑盾）、破阵者（重锤铁甲）、引星者（法杖）；选择不耗时，其他行动开始后不能再选。全程可换装。
- 剑出手快；重锤耗时较长、抵消守卫部分护甲；法杖可在视线内施法，消耗法力，随已支付规则 tick 恢复。使用装备的射程/费用进入公开视图，动画不决定消耗。
- 新远程敌人瞄准公开锁定格，下一截止命中，移动或关门阻断可反制；游击敌人相邻攻击后后撤。重甲守卫保留原蓄力逻辑；新增规则仅影响 Alpha。
- 六层均为连续走廊，每层对之间两条梯路，形成左右环路。中部门闩有普通门与需拉杆开启的栅门；可绕另一侧梯子。关闭的门阻断穿行与视线。
- 分支提供一次性补给事件：付金币或付生命开启，奖励确定实例落地，不受背包容量影响；拒绝支付不耗时、不改变 RNG。拉杆和事件由模拟拥有并存档；UI 只呈现可见/已探索信息。
- 整体验收包含各配装公开自然通关与分支、不同种子拓扑/内容、战斗反制受控反例、旧四场景黄金兼容。数值在 Alpha 本地验收前可校准，最终身份包含完整 Alpha 内容。
